# Турникмен / Pullup Bot

Telegram-бот для систематического прогресса в четырёх упражнениях: **подтягивания, отжимания, брусья, приседания**. Строит персональный план, адаптирует нагрузку, отслеживает прогресс и мотивирует команду.

## Возможности

### Тренировочный план
- Четыре упражнения с независимыми нормами: подтягивания, отжимания, брусья, приседания
- Один общий календарь: тип дня (Средний/Лёгкий/Тяжёлый/Отдых/Плотность) задаёт нагрузку для любого выбранного упражнения
- Кнопка «Тренировка» → выбор упражнения; хотя бы одно упражнение в день — день засчитан
- Волновой 7-дневный цикл: Средний → Лёгкий → Тяжёлый → Отдых → Плотность → Лёгкий → Отдых (программы: Стандарт 5х, Новичок 3х, Продвинутый 6х)
- Автоматическая прогрессия per-exercise: после стабильного цикла норма +5%
- Корректировка по RPE (скользящее среднее 3 сессий упражнения): высокий RPE → нагрузка снижается, низкий → повышается
- Новые упражнения настраиваются при первом выборе (бот спрашивает максимум за подход)

### XP и ранги (CS:GO)
18 рангов от Silver I до The Global Elite (0 – 70 000 XP):

| Группа | Ранги | XP |
|---|---|---|
| Silver | I · II · III · IV · Elite · Elite Master | 0 – 4 000 |
| Gold Nova | I · II · III · Master | 5 500 – 13 500 |
| Master Guardian | I · II · Elite · DMG | 18 000 – 36 000 |
| Eagle | Legendary Eagle · LEM | 44 000 – 53 000 |
| — | Supreme Master First Class | 63 000 |
| — | The Global Elite | 70 000 |

Начисление XP: +1 за подтягивание, +0.75 за отжимание на брусьях, +0.5 за отжимание, +0.25 за приседание, +50 за каждый день стрика подряд.

### Стрик и заморозки
- Стрик считает дни подряд с тренировкой или отдыхом
- Токены заморозки защищают стрик при пропуске дня
- Зарабатываются: каждые 7 дней стрика, при повышении ранга, при новом личном рекорде
- Максимум 5 токенов

### Кочка недели
Каждый понедельник автоматически выбирается участник с наибольшим XP за прошедшую неделю (все упражнения, с учётом весов XP). Все участники получают уведомление с топ-3, победитель носит значок 👑 в рейтинге и статистике до следующего понедельника.

### Социальные функции
- Список участников с прогрессом каждого (сегодняшний план по упражнениям, стрик)
- Отправка мотивации друзьям одной кнопкой
- Уведомления о новых участниках с кнопкой приветствия
- Недельный рейтинг по XP

### Турникмен AI
Полноценный чат-ассистент на базе **Google Gemini 3 Flash** (`gemini-3-flash-preview`, бесплатный тир).

- Знает полную историю тренировок пользователя, его ранг, стрик, базу и план на завтра
- Поддерживает многоходовой диалог — помнит контекст до 10 предыдущих обменов
- Может ответить на любой вопрос о тренировках, технике, функциях бота или личном прогрессе
- Лимиты бесплатного тира: 15 запросов/мин, 1 500 запросов/день; при превышении бот сообщает об этом пользователю
- Системный промпт содержит полную базу знаний о боте и актуальные данные пользователя — ответы персонализированы с первого сообщения

### Прочее
- История тренировок с постраничной навигацией по неделям (по упражнениям)
- Редактирование прошлых дней per-exercise (в т.ч. удаление с откатом XP и program_day)
- Настройка времени уведомлений, имени, норм по каждому упражнению
- Причина пропуска восстанавливает стрик; токены заморозки тратятся автоматически
- Экспорт всей истории в CSV
- Многоязычность: русский и английский
- Полная админ-панель: управление пользователями, рассылка, баг-репорты, статистика, режим обслуживания

## Установка и проверка

Поддерживаются Python 3.12 и 3.13. Полный набор закреплённых зависимостей для
разработки и CI находится в `requirements-dev.lock`; прямые зависимости приложения
перечислены в `requirements.txt`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest pullup_bot/tests -q
```

В Linux используйте `.venv/bin/python`. CI запускает этот набор проверок на обеих
версиях Python. После изменения зависимостей обновляйте lock-файл в чистой `.venv`
и проверяйте `pip check` и тесты.

## Локальный запуск

Создайте `~/.env.pullup_bot`:

```
PULLUP_BOT_TOKEN=...
PULLUP_SECRET=...
ADMIN_TG_ID=...
GEMINI_API_KEY=...
TZ_OFFSET_HOURS=5
```

```bash
python -m pullup_bot --allow-local
```

Для локальной разработки используйте отдельный токен Telegram-бота и отдельные
пути `PULLUP_DB`/`PULLUP_FSM_DB`. Обычный production-запуск разрешён только через
systemd, чтобы случайно не запустить второй экземпляр с тем же токеном.

Polling используется по умолчанию. Для webhook задайте `WEBHOOK_URL` вида
`https://example.com/webhook` и непустой `WEBHOOK_SECRET` из 1–256 латинских букв,
цифр, `_` или `-`; без секрета запуск запрещён. Администратор определяется только
по `ADMIN_TG_ID`. Все календарные даты и задания используют `TZ_OFFSET_HOURS`.

## Деплой на сервер

Обновите `CHANGELOG.md`, закоммитьте изменения в отдельную ветку и откройте PR.
Ветка должна включать все необходимые предыдущие изменения; слияние PR требует
одобрения владельца проекта.

```bash
# из локальной папки проекта
./deploy.bat
```

`deploy.bat` вызывает `deploy.ps1`: проверяет чистоту отслеживаемых файлов,
запрещает `main`/`master`, пушит текущую ветку и передаёт серверу точный SHA.
При ошибке выполнение прекращается. Адрес и SSH-ключ можно переопределить:

```powershell
.\deploy.ps1 -Server user@host -SshKey C:\path\to\key
```

Серверный `scripts/deploy_server.sh` создаёт отдельный релиз и `.venv`, устанавливает
зависимости и запускает тесты до остановки работающего бота. Затем делает снимки
обеих SQLite-баз через backup API, переключает systemd на релиз и проверяет запуск.
При ошибке запуска восстанавливается предыдущая конфигурация сервиса; снимки БД
сохраняются в `~/pullup-releases/<release>/backups`. Базы автоматически назад не
откатываются, чтобы не потерять поступившие данные. Каталоги релизов и резервных
копий сохраняются для ручного восстановления. `~/deploy.sh` становится обёрткой,
которой требуются ветка и SHA, и больше не подтягивает `main` в рабочую ветку.

Локальный `auto_fix_bugs.ps1` теперь только читает одобренные баг-репорты и сохраняет
план проверки в `.audit-plans/`. Его агенту доступны только инструменты чтения;
автоматические изменения, push и деплой отключены.

Секреты хранятся в `~/.env.pullup_bot` соответствующего окружения и не коммитятся в Git.
